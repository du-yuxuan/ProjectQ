# Q 多端文档 · 云端后端（Node.js）

> 技术栈：Node.js + Express + ws + Prisma
> 定位：StepAudio 中转 + 编排大脑 + 持久化 + 铸证。所有端的公共服务。

---

## 一、模块架构

```
backend
├── ws/
│   ├── glass-session.ts    眼镜端 WSS（音频上行 + 评分下行）
│   └── mobile-lite.ts      手机轻量版 WSS
├── services/
│   ├── stepaudio-relay.ts  StepAudio 2.5 Realtime WS 代理
│   ├── orchestrator.ts     编排：拦截响应、聚合、里程碑检测
│   ├── pace-calculator.ts  语速引擎
│   ├── stutter-detector.ts 卡壳检测规则引擎
│   ├── profile-engine.ts   跨会话记忆 → 能力画像 + 阈值自适应(EMA)
│   └── injective.ts        CosmWasm soulbound 铸证
├── routes/                 REST: session/profile/credential/feedback
└── db/ (Prisma + SQLite→Postgres)
```

---

## 二、编排核心（替代 Dify）

```
音频流 → StepAudio → JSON 响应
   ├─ score      → 聚合到 Segment，融合眼镜端接收度
   ├─ hook       → 转发眼镜端 HUD + 启动倒计时
   ├─ recovery   → 记录 responseTimeMs → EMA 更新用户基准
   └─ segment_end→ 持久化 + 里程碑检测 → Injective
```

## 三、语速算法（引擎实现）

双源融合：客户端能量包络（有声/无声）+ StepAudio 文本时间戳。

```
滑动窗口 5s，每秒更新：
  纯说话时长 = 窗口内 isActive 的时间段总和
  有效字数   = 总汉字数 - 填充词数（嗯/啊/呃/那个/就是/然后/其实/反正/基本上）
  净语速     = 有效字数 / 纯说话时长 (chars/s)

归一化（中文演讲舒适区 200-280 字/分 ≈ 3.3-4.7 chars/s）：
  <1.5 过慢 0-2 | 1.5-2.5 偏慢 3-5 | 2.5-3.3 正常偏慢 6-7
  3.3-4.7 舒适 8-9 | 4.7-5.5 偏快 6-7 | 5.5-6.5 赶 3-5 | >6.5 过快 0-2

综合语速分 = 净语速分×0.6 + (1-停顿率)×10×0.4
```

卡壳触发规则（限频：同类型 8s 内不重复）：
- 停顿 >2s → 开口兜底
- 填充词密度 >3次/10字 + 停顿 >1.5s → 思路兜底
- 句中断裂（有声→>1.5s无声→有声且不连贯）→ 衔接兜底
- 语速偏离基准 >40% 持续 3s → 节奏兜底
