# 决策：自训练模型（学习成长 Loop）要不要做？

> 决策日期：2026-07-23
> 结论：**做"追踪式进化 Loop"，不做真 ML 自训练。**

---

## 一、结论先行

做 Loop（学习成长），但实现成 **"事件记录 + 用户画像 + 阈值自适应"的规则式个性化**，**不**做真正的 ML 模型在线训练/微调。

## 二、为什么不做真 ML 自训练

1. **72h 风险极高**：在线学习/微调要数据、要调参、要验证"真的变好了"。做不好=模型没进化=demo 砸。
2. **不可见的失败**：真训练若没明显改善，"可见进化" wow moment 直接消失，反而负分。
3. **不是核心**：项目的核心 wow 是"冻住->递钩->开口"（①③），进化是加分层。把 72h 押在风险最高的加分层不划算。

## 三、为什么"追踪式进化 Loop"够用且该做

"可见进化"是三件事的基石，必须要有（只是用稳的方式实现）：
- **2026 loop 的 wow**：卡点图谱随使用收紧 = 评委看得见的进化
- **Injective 凭证的依据**：改进铸证需要追踪到"卡壳率↓"
- **superun 评审**："AI 真正改变流程"--自适应你的模式才算真改变

而"追踪式进化"能给到这三件事，且 72h 可做：
- 每次触发记录一条 {情境, 卡点类型, 垫法, 是否恢复}
- 聚合成"卡点图谱"（情境×类型×有效垫法）
- 阈值自适应：你高频卡壳的情境，降低触发阈值（更早出手）
- 这就是"自训练"在产品层的实际含义：**系统记住你的模式并调整自己**，只是用规则+记忆实现，不用梯度下降

## 四、具体怎么做（72h 可交付）

```
事件记录层：每次①②③④触发 + 反思(按键/状态恢复) -> 存一条事件
   ↓
用户画像层：聚合成卡点图谱 {情境×类型×有效垫法×频率}
   ↓
自适应层：高频卡壳情境 -> 降低触发阈值；有效垫法 -> 优先用
   ↓
可见进化：卡点图谱可视化(热力图)，随使用收紧
   ↓
铸证：某情境卡壳率↓达里程碑 -> Injective soulbound 凭证
```

技术栈：Dify（记忆+工作流）+ 简单存储（卡点图谱）+ 前端可视化。**不需要训练框架、不需要 GPU、不需要调参。**

## 五、诚实边界

- 这是"规则式个性化"，不是"模型权重学习"。对外可称"自训练/学习成长 Loop"（系统确实在学习你的模式），但技术上别宣称"模型微调"（评委一问就穿）。
- demo 时若实时数据不够，可用"预录的真实事件序列"驱动卡点图谱进化动画--只要事件是真实记录的，不算造假。

## 六、一句话

> 做 Loop（追踪进化+自适应+铸证），不赌真 ML 训练。用规则+记忆实现"系统越用越懂你"，72h 稳交付，且保住"可见进化"的 wow 和 Injective 凭证的依据。
