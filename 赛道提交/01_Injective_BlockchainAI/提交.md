### 1. 项目名称、简介（Pitch）
**Q（Cue）**：一副感知你表达状态的穿戴设备（眼镜+指环），在你沟通冻住时递一个钩子解冻，并把**传感器验证的沟通力改进铸成 Injective 链上可信凭证**--把"我沟通能力强"这个平时完全不可证的软技能，变成可携带、防篡改的链上证明。

### 6. Injective 开发过程是否遇到困难？

CosmWasm 合约（Rust）已编译通过（224KB wasm，含 soulbound 守卫、里程碑类型枚举、admin-only mint），但后端 SDK 集成遇到主要困难：

1. **@injectivelabs/sdk-ts 未能完整安装集成**：SDK 依赖较重，黑客松时间约束下，完整的 WalletStrategy → MsgExecuteContract → MsgBroadcaster 链上交易路径已设计并写入代码（`backend/src/services/injective.ts`），但实际降级为模拟铸证（返回模拟交易哈希，仅写数据库，不上链）。
2. **合约已编译但未部署到测试网**：`injective/src/lib.rs` 编译产出 wasm，但 `INJECTIVE_CONTRACT_ADDRESS` 仍为空，合约尚未 store + instantiate 到 injective-888 测试网。
3. **非 Web 客户端钱包连接**：PICO Unity 端需通过 WalletConnect 二维码让用户手机钱包扫码授权，但 Injective 文档主要面向 Web 前端，Unity/C# 的 WalletConnect 集成示例较少，我们只能自行设计"PICO 显示二维码 → 手机扫码 → 后端中转地址"的桥接方案。

### 7. Injective 开发资料帮助了哪些？

1. **WalletStrategy 统一接口**：docs.injective.network 钱包连接文档清晰说明了 WalletStrategy 如何一套代码适配 Keplr / MetaMask / WalletConnect / Leap / Ledger，我们直接复用这一抽象层设计后端钱包服务。
2. **MsgBroadcaster 一次调用签名+广播**：交易提交只需一次函数调用，省去手动组装交易+签名+广播的繁琐，铸证流程因此能精简为"构造 ExecuteMsg → 广播 → 返回哈希"三步。
3. **CosmWasm 标准库**：cosmwasm-std 2.1 的 entry_point / Storage / Response 等 API 帮助快速实现 soulbound 凭证合约（Transfer 始终返回错误、mint 设 admin 白名单）。
4. **sdk-ts TypeScript 类型定义**：MsgExecuteContract.fromJSON 等接口类型定义让集成路径可读性强，即便未完全跑通，代码注释中的完整调用路径也清晰可审。

### 8. Injective 开发资料需要改进哪些？

1. **sdk-ts 安装/依赖偏重**：建议提供更轻量的最小集成包（仅含交易构造+广播，不含完整钱包策略），降低非全栈区块链项目的接入门槛。
2. **缺少非 Web 客户端集成示例**：WalletConnect 在 Unity/C# 等游戏引擎客户端的集成没有官方示例，需要自行摸索桥接方案。
3. **CosmWasm 部署端到端教程可更详细**：从 `injectived tx wasm store` 到 instantiate 再到配置 contract_address 的完整流程，建议补充更多实战示例（尤其测试网 gas/fees 配置）。
4. **soulbound token 缺少官方模板**：CosmWasm 没有 CW721 soulbound 的标准实现，需自行实现 Transfer 拒绝逻辑，建议提供官方 soulbound 合约模板。

## 为什么 Injective 是"必要"而非装饰
沟通力平时不可证 -> 硬件测了才可信 -> 链上存证才可携带。三环缺一不可。轻质押/治理角：经验证的讲者可质押链上声誉承接高利害沟通场景。

## 一句话定位
> Q：把传感器验证的"沟通力改进"铸成 Injective 链上凭证--让不可证的能力，变成可携带的证明。
